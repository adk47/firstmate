# Credit cleanup cases

Part of the `customer-data-resolution` skill. The safety rules in its `SKILL.md` bind every case here and win over anything in this file.

Read before any credit removal, raw unlink, merge, or delete (SKILL.md Procedure step 3).

## Merge-scope anchor (SKILL.md Profile merge safety rule)

When one case contains both a true duplicate and a same-name different artist, merge only the customer-confirmed duplicate and remove only the exact misassigned rows while preserving legitimate releases. Do not broaden the resolution into a merge or reopen older requests without separate evidence.

- Removal list: normalize title+artist, deduplicate IDs, compare provenance, and canary one. Stop before any delete when a requested row is ambiguous: a title+artist that matches more than one live association, no association, or a different profile than the one named. Report the ambiguous rows and the pass condition instead of guessing; this refusal covers non-primary roles, which the Primary-artist collision protocol below does not. If every role on an owned profile+track pair is disputed, an allowlisted resolver may audited-delete that exact pair; otherwise remove only named roles. For all-track cleanup, enumerate associations, rebuild collaborators, and require zero in admin, public credits, and no-cache HTML. If API is zero but HTML remains, file one profile `data_verification` and do not repeat absent writes.
- Primary-artist collision: require the exact Primary Artist tracks to keep; snapshot and hash all other live Primary Artist track IDs. Remove only that role with `DELETE /admin/track/<track_id>/profile/<profile_id>/credits?force=true` and `{"credits":["Primary Artist"]}`—never delete/re-add a pair when other roles remain. Canary one. At the bulk threshold cite the allowlisted requester’s exact-set decision with `--confirmed-by`, message ID, author ID, and channel. After interruption regenerate the live remaining-set count/hash and resume only it. Finish when remaining Primary Artist IDs equal the keep set, no pre-existing non-primary role was lost, and collaborator rebuild/list reads agree; newly surfaced non-primary roles are preserved data when existing-role loss is zero.
- Same-name collision: verify tracks, claims, roles, and hierarchy. Add missing child roles to the claimed destination before removing wrong roles. If every track is already correct there, never merge or re-add: canary-delete one exact wrong pair, verify zero wrong/one intended, remove the exact remainder, then rebuild and read both collaborator directions. Pass bulk authorization fields; update the customer only after bilateral proof.
- Mixed-source collision: prohibit merge, whole-source unlink, and provenance-free delete/re-add. Enumerate recording+role tuples and destination/claim/workspace lineage; regenerate and hash the UUID+ISRC+role manifest immediately before writing. Require track proof for ambiguous roles and authorization naming source, destination, hash, roles, and consolidation. Apply tuple-level exclusion plus provenance-preserving re-home; verify both profiles immediately and after the next pipeline cycle.
